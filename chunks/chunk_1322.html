2. What "AI Gateway" actually means in 2026

By 2026 the term "AI Gateway" has converged to mean a single substrate that handles six primitives across LLM + MCP + agent traffic:

  1. Routing — choose a provider/model per-call (cost, latency, capability, region, failover).
  2. Fallbacks — if provider A times out, route to B; if B returns 529, route to C; preserve semantic-cache hint.
  3. Semantic caching — cache identical or near-identical prompts at the edge or in your control plane; emit semantic_cache_hit flag in observability.
  4. Provider credential isolation — store provider API keys in a vault with virtual keys per tenant/team, never in app code.
  5. LLM observability — per-call trace + token + cost + latency + status + guardrail decision + audit-export.
  6. Audit / EU AI Act — immutable per-call ledger with EU AI Act Art. 13 logging + Art. 14 human-oversight primitive.

If a product claims "AI Gateway" and doesn't ship all six, it's either an LLM observability tool (Helicone, Langfuse, LangSmith, Arize, Maxim) or an LLM proxy (raw OpenAI-compatible proxy) — both legitimate but not the same category.

Best for: teams that want a control plane, not an SDK. If your engineering leadership is buying, not building, Portkey is the default.   • Deployment: SaaS only (no self-host).
  • Provider catalog: 25+ primary integrations + 250+ via route-catalog abstraction.
  • Virtual keys + provider credential vault: Yes — Vault with BYOC, per-tenant rate limits.
