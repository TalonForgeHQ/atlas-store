5. Native Parquet / JSON / Arrow readers

The first-party data overview pages enumerate first-class Parquet, JSON, CSV, and Arrow readers — DuckDB's read_parquet, read_json_auto, read_csv_auto, and read_arrow are first-class top-level readers with predicate pushdown into Parquet metadata + native Arrow record-batch ingestion. AI agents that ingest LLM-tool-output columnar payloads can read directly into DuckDB without an intermediate transformation step.

6. Extensions and Substrait interchange

The first-party extensions page enumerates community-maintained extensions: httpfs (S3 / GCS / Azure remote file reads), json (native JSONL ingest + read_json_auto), parquet, icu (locale-aware collation), spatial (GEOMETRY + DuckDB-spatial companion), mysql / postgres (foreign-DB scanner), iceberg (Apache Iceberg catalog reader), delta (Delta Lake integration), excel (.xlsx ingest), and substrait (cross-engine query-plan interchange). Substrait support means DuckDB can ship an analytical plan to another Substrait-compatible engine (Apache Arrow DataFusion, Apache Gluten, etc.) without rewriting SQL.

7. The Quack Remote Protocol

The first-party nav-menu on duckdb.org lists docs/current/quack/overview as a first-class documentation surface. Quack is DuckDB's wire-compatible remote access protocol — agents that link-load the DuckDB library locally can also open a Quack-wrapped remote DuckDB instance, supporting hybrid local+remote patterns.
