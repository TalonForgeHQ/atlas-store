2. HyperAgent: open-source, Playwright-powered, AI-native

Official HyperAgent documentation calls HyperAgent an open-source tool that “supercharges Playwright with AI.” Its core interfaces include page.ai(), page.extract(), and executeTask(), while regular Playwright remains available when deterministic browser code is the better fit.

This positions Hyperbrowser between pure browser infrastructure and managed computer-use agents: developers can run HyperAgent locally or select Hyperbrowser as the production browser provider.

3. MCP integration: client, not server

Hyperbrowser's MCP documentation is explicit: “HyperAgent functions as a fully functional MCP (Model Context Protocol) client.” The product connects to external MCP servers such as Google Sheets, Notion, and Slack so a browser task can continue into a broader workflow.

  • Verified: HyperAgent initializes an MCP client and consumes tools from configured MCP servers.
  • Not claimed: Hyperbrowser does not document a native MCP server that exposes the browser itself as a Claude or Cursor tool.
  • Buyer implication: audit scope should join browser actions to external MCP tool calls, including server identity, tool name, arguments hash, result hash, and authorization context.

4. Persistent profiles across sessions

Official Profiles documentation says profiles persist cookies, local storage, session storage, and cache across multiple sessions. A profile is a saved browser user-data directory that can be attached to future sessions.

This is the strongest durable-identity primitive in the Hyperbrowser surface. It supports maintained login state and multi-session workflows, but it also creates governance questions: who can attach a profile, which session changed it, how long state is retained, and how profile deletion is evidenced.
